# Идеи для дальнейшей кастомизации пустого экрана консоли (матричный дождь)

Отложено 2026-08-21 — сделано в тот же заход: символ заливки букв
(`emptyStateFillChar`) и алфавит символов дождя (`emptyStateRainChars`).
Остальное — черновик идей, не начинать без обсуждения с пользователем,
формат/названия пропсов ниже — черновые, не финальные.

## 1. Направление анимации (сверху/сбоку)

Сейчас дождь всегда падает сверху вниз, по колонкам (`rainColumns`, `column.head`
растёт построчно вниз в `renderRainFrame`/`spawnColumn`). Чтобы сделать
направление настраиваемым (сверху/слева/справа/снизу), понадобится:

- Обобщить модель колонки на "полосу" вдоль ЛЮБОЙ из двух осей — сейчас код
  жёстко привязан к rows/cols именно как вертикаль/горизонталь дождя.
- Для горизонтального направления — транспонировать логику rows↔cols в
  `renderRainFrame`, `buildNoSignalMask` (маска сейчас строится в
  системе координат "строка/колонка", а не абстрактно).
- `BOTTOM_FADE_ROWS` (угасание у низа) нужно тоже сделать направленным —
  сейчас это буквально "снизу", при другом направлении угасание должно быть
  у противоположного от источника края.

Реализуемо, но трогает почти весь рендер-цикл — не мелкая правка.

## 2. Дождь "внутри" силуэта букв (вместо огибания)

Сейчас `rainMask[r][c] === true` означает "тут буква, дождь не идёт, рисуем
`getFillChar()` статично" — то есть маска исключает дождь из зоны букв.
Обратный режим — дождь идёт ТОЛЬКО внутри буквы, снаружи пусто (или наоборот,
снаружи дождь, а буква — пустая дыра, что уже частично есть сейчас с другим
знаком). Технически это инверсия одного условия в `renderRainFrame`:

```
if (rainMask[r]?.[c]) { /* сейчас: статичная заливка */ }
```

— но чтобы дождь именно "падал" ВНУТРИ буквы (а не просто перекрашивал
статичные клетки), колонкам (`rainColumns`) нужно либо иметь свои независимые
"головы" в пределах каждой буквы отдельно, либо ограничивать видимость
существующих колонок маской буквы, а не наоборот. Второе — проще: инвертировать
`inAmbientZone`/маску-условие видимости дождя. Стоит попробовать сначала как
маленький эксперимент (флаг `invertMask?: boolean`), не большая переработка.

## 3. "Полосы" — уточнить у пользователя, что именно имелось в виду

Пользователь упомянул "настройка полосы" без уточнения — не ясно, это про:
- ширину/плотность колонок дождя (`RainColumn.length`, `speed` — уже
  рандомизированы в диапазоне, можно вынести диапазон в пропсы),
- либо какой-то визуальный "band"/полосу-разделитель на экране,
- либо что-то третье.

Не начинать реализацию, пока не переспрошено конкретно.

## Общий контекст

Все эти пропсы (если делать) идут по той же цепочке, что уже есть для
text/scale/letterGap/fillChar/rainChars:
`BaseTerminal.vue` (props) → `console-manager.ts` (`ConsoleManagerContext`) →
`layout.vue` (прокидывает в `<BaseTerminal>`) → `Logs.vue` (читает
`modlex-settings.ts` refs, кладёт в `provideConsoleManager({...})`) →
UI в `ModLexSettings.vue` (+ localStorage-ref в `modlex-settings.ts`).

Пользователь сам отметил риск: "слишком большая свобода настроек" — не
добавлять всё это одним заходом, дробить на отдельные обсуждения.
